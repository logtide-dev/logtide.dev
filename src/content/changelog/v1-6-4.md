This release is about Odoo: LogTide can now read Odoo's log format directly and turn Odoo Automated Actions into log entries. It ships together with the [Odoo integration guide](/integrations/odoo/), the `logtide_odoo` addon for Odoo 17.0 to 20.0, and version 0.11.0 of the Python SDK, which keeps working in prefork servers such as Odoo with `workers > 0`.

**Before upgrading:** migration 078 runs on startup and only widens the list of receiver types. On ClickHouse installs, pull the updated `docker/clickhouse-system-logs.xml` and restart ClickHouse once (`docker compose restart clickhouse`): the ClickHouse image did not change, so a plain `docker compose up -d` leaves it running with the old log level.

### Added

- **Odoo log parser**: new built-in `odoo` parser for pipeline steps. It reads Odoo's default log format (`timestamp pid LEVEL db logger: message`) into `timestamp`, `pid`, `level`, `odoo_level`, `dbname`, `logger` and `message`. On `werkzeug` access lines it also extracts `client_ip`, `http_method`, `http_path`, `http_status` and Odoo's performance counters: `query_count`, `query_time`, `remaining_time` and `duration_ms`, so slow requests and requests with too many SQL queries can be filtered and charted. ANSI colors are stripped first. Tracebacks span several lines, so join them in the shipper, for example with a Fluent Bit multiline parser.
- **Odoo receiver**: new `odoo` receiver type for Odoo 17+ Automated Actions with "Send Webhook Notification". Each call becomes one log entry (`<model> <name> → <state>`, e.g. `account.move INV/2026/0042 → posted`) with the record fields under `metadata.odoo.fields`. Cancelled or failed states are logged as `warn`, and a `levelMap` in the field mapping can override that. This is the way to get events out of Odoo Online, where custom modules are not allowed. See [Webhook Receivers](/docs/receivers/#odoo).

### Changed

- **ClickHouse server log at warning level**: the bundled ClickHouse config now sets the server's own log (`clickhouse-server.log`) to `warning` instead of the image default `trace`. At trace level it was the largest source of disk writes left after 1.6.3, about 2 MiB/s on a busy instance. To debug ClickHouse itself, raise the level again in `docker/clickhouse-system-logs.xml`.
