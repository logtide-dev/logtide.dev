A maintenance release with two fixes for things that were shipped but hard to reach, and one change for anyone who runs LogTide with limits: the limits are now visible before an error tells you about them.

**Before upgrading:** migration 080 runs on startup. It adds two nullable columns to `users` for the per-user organization limits. Nothing changes for existing data, and an instance that sets no limits looks and behaves as before.

### Added

- **Limits shown before you hit them**: the project limit of an organization and the per-user organization limits used to surface only as an error after the attempt. The Projects page now shows the count against the limit, for example "2 of 2 projects". At the limit it explains why, links owners and admins to plan and usage, and turns off "New project" and "Restore". The "Create organization" dialog shows how many organizations you own and how many you created this month against your limits, and says which limit is reached instead of letting the request fail.
- **Per-user organization limits**: `MAX_ORGANIZATIONS_PER_USER` and `MAX_ORGANIZATION_CREATIONS_PER_USER_PER_MONTH` apply to every user of an instance. An instance administrator can now replace either one for a single user from Admin > Users > (user) > Organization limits. Each limit is the instance setting, a custom number or no limit, and 0 stops the user from owning or creating organizations. It also applies to ownership transfers and on instances that set no limit. Changes are recorded in the audit log.
- **IP ranges in API key allowlists**: the "Allowed origins and IPs" list of an API key accepts CIDR ranges such as `203.0.113.0/24` and `2001:db8::/64` next to single addresses, origins and hostnames. A range that is not valid CIDR is refused when the key is created.
- **Second IP reputation source**: SIEM enrichment now also checks the [NetAPI honeypot feed](https://netapi.com/compromised-ips/), the IPv4 addresses that attacked NetAPI's sensor network in the last 48 hours. An address on it is marked malicious with source `NetAPI`, and everything else gets the IPsum verdict as before. The list is refreshed hourly and is CC BY 4.0, with the attribution shown on every hit. Turn it off with `NETAPI_REPUTATION_ENABLED=false`. Contributed by @slavaolesik.

### Fixed

- **Hardware Health detection pack missing from the gallery**: the pack shipped in 1.7.0, but no page listed its category, so it could not be enabled from the UI. It is now in Alerts > Detection packs with the other operational packs, where the [Hardware Health docs](/docs/hardware-health/#detection-pack) already pointed.
- **API key IP allowlist rejecting allowed clients**: addresses were compared as text, so `203.0.113.7` did not match a client seen as `::ffff:203.0.113.7`, the usual form on a dual-stack listener, and an IPv6 address had to be typed exactly as the server spells it. Addresses are now compared by value. A listed IP is also accepted when the request carries an `Origin` header, and the 403 names the address the server saw. Behind a reverse proxy or Cloudflare that address is the proxy's own until [`TRUST_PROXY`](/docs/deployment/#trust-proxy) is set.
- **Organization limit error showed a code**: creating an organization over a limit showed `organization_limit_reached` instead of the sentence the server sends with it.
